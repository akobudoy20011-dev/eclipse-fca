# Security Policy

## Supported versions

Security fixes are applied to the current development line on `main`. Older snapshots may not receive security updates; use the latest reviewed release or commit and check the release notes.

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities in public issues, pull requests, discussions, or social posts.

Use GitHub's **Private vulnerability reporting** feature on this repository when it is available. If that feature is unavailable, contact the repository maintainer privately through the contact method listed on the maintainer's GitHub profile. Include:
- affected commit, version, or file;
- impact and realistic attack conditions;
- minimal reproduction steps or a proof of concept that does not access other users' data;
- any suggested mitigation.

Do not include live cookies, appState values, access tokens, proxy credentials, personal data, or unredacted session/network captures in a report.

Please allow maintainers reasonable time to investigate and coordinate a fix before public disclosure. Do not test against accounts, systems, or sessions you do not own or have explicit permission to assess.

## Project security boundaries

ECLIPSE-FCA is an unofficial client foundation. It does not authorize access to accounts or services. Users must use only accounts and sessions they are authorized to access and must respect applicable platform terms, security challenges, and rate limits.
